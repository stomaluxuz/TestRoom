# TestRoom — тесты по коду в Telegram

Преподаватель загружает тест, нажимает «Активировать» и получает 6-значный код.
Студенты вводят код в Mini App и решают тест с таймером. Учитель в реальном времени
видит, кто сколько решил и кто сворачивал приложение, а потом получает итоги и Excel.

## Что внутри

```
app/
  main.py      запуск: сервер Mini App + бот + автозакрытие тестов по времени
  bot.py       Telegram-бот: ФИО, заявки учителей, загрузка тестов файлом, админ-команды
  api.py       API для Mini App
  services.py  вся логика: тесты, запуски с кодом, ответы, статистика, Excel
  parsers.py   разбор Word / Excel / txt без нейросети
  models.py    таблицы базы данных
  auth.py      проверка подписи Telegram (подделать вход нельзя)
webapp/        Mini App (учитель и студент): index.html, app.js, style.css
tests/         39 автотестов
loadtest/      нагрузочный тест
```

## Быстрый старт на Windows (для проверки)

1. **Python 3.11+** должен быть установлен (при установке отметьте «Add Python to PATH»).
2. **Создайте бота:** в Telegram откройте @BotFather → `/newbot` → получите токен.
3. **Узнайте свой Telegram ID:** напишите @userinfobot.
4. Распакуйте архив, дважды щёлкните **`setup.bat`**: создастся окружение и файл `.env`.
5. Откройте `.env` в Блокноте и впишите только `BOT_TOKEN` (от BotFather) и `ADMIN_IDS` (ваш ID).
   `WEBAPP_URL` заполнять не нужно — его подставит запуск.
6. Запустите **`start.bat`**. Он сам поднимет https-туннель (cloudflared), пропишет адрес в
   `WEBAPP_URL` и запустит сервер с ботом. **Не закрывайте это окно** во время работы.
   - `cloudflared.exe` уже лежит в папке проекта. Если его нет — скачайте
     `cloudflared-windows-amd64.exe` (cloudflare.com → Zero Trust → Downloads) и положите рядом.
   - Адрес туннеля новый при каждом запуске — скрипт подставляет его автоматически, вручную ничего копировать не нужно.
7. Откройте бота в Telegram → `/start` и нажмите нижнюю кнопку **«Тесты»**.

   Проверить, что всё работает: **`test.bat`** запускает 40 автотестов.
   (`run.bat` тоже остался — он запускает только сервер, без туннеля, если `WEBAPP_URL` уже задан.)

Вы админ, поэтому сразу являетесь и преподавателем. Адрес бесплатного туннеля меняется
при каждом запуске, поэтому для постоянной работы нужен сервер (ниже).

## Как пользоваться

**Преподаватель**
1. Нажимает в боте «Я преподаватель», пишет вуз и предмет. Вам (админу) приходит заявка
   с кнопками «Одобрить / Отклонить».
2. Загружает тест: отправляет боту файл или нажимает «Загрузить тест» в приложении.
   Шаблоны файлов: команда `/template`.
3. В приложении выбирает тест → группа, время, число вопросов → **«Активировать тест»**.
4. Говорит студентам код, смотрит живую статистику, после окончания открывает итоги
   и нажимает «Получить Excel в чат».

**Студент:** `/start` → ФИО → кнопка «Тесты» → ввести код → решать.

### Форматы файлов

Word (.docx) или .txt — варианты с буквами, правильный помечается звёздочкой `*` перед буквой,
номер вопроса необязателен:
```
1. Самая длинная кость?
*A) Бедренная
B) Плечевая
C) Лучевая
```
Также понимаются: старый формат «+/−» (правильный `+`, неправильные `−`) и формат систем
тестирования (HEMIS и похожие): `++++` между вопросами, `====` между вариантами, `#` перед правильным.

Excel (.xlsx): `Вопрос | Вариант A | Вариант B | ... | Ответ`, где ответ — буква (A/B/C или А/Б/В),
номер (1, 2, 3) или текст правильного варианта.

Бот проверяет файл и точно пишет, в каком вопросе ошибка («№12: не отмечен правильный ответ»).
Можно сохранить только правильные вопросы, а остальные дописать в приложении.

> ⚠️ Если Word сам превратил строку в маркированный список (значок «*» или «-» пропал из текста),
> уберите маркеры (Главная → Маркеры) или используйте готовый шаблон.

### Защита от списывания
- у каждого студента свой порядок вопросов и вариантов;
- одна попытка на человека, вернуться к прошлому вопросу нельзя;
- правильные ответы не передаются в приложение до конца теста;
- сворачивание Telegram фиксируется: учитель видит, сколько раз и на сколько секунд
  студент уходил; после N раз (настраивается, 0 — выключено) тест студенту закрывается;
- учитель видит всех вошедших и может удалить лишнего; можно ограничить число участников.
- подбирать код программой нельзя: после 10 неверных кодов за 10 минут вход временно блокируется.

## Админ-панель (для вас)

В приложении у админа есть пункт **«🛠 Админ-панель»**:
- все преподаватели: тесты, запуски, сколько студентов прошли, тариф; поиск по ФИО, @username, вузу или ID;
- заявки (они всегда сверху): одобрить или отклонить, преподаватель сразу получает уведомление в боте;
- выдать Pro на нужное число дней, заблокировать или разблокировать, написать преподавателю в Telegram;
- **«Открыть кабинет преподавателя»**: вы видите и делаете всё то же, что он сам (загрузить
  или исправить тест, запустить, посмотреть результаты). Сверху горит оранжевая плашка
  «Кабинет: ФИО» с кнопкой «Выйти». Excel из чужого кабинета приходит вам, а не учителю;
- **журнал действий**: каждый вход в кабинет и каждое изменение записываются (кто, у кого, что, когда).

Совет: укажите в условиях использования сервиса, что поддержка может заходить в кабинет
для помощи. Так честнее перед преподавателями.

## Команды админа в боте
| Команда | Что делает |
|---|---|
| `/stats` | статистика сервиса |
| `/pending` | заявки преподавателей |
| `/teachers` | список преподавателей |
| `/give_pro ID ДНЕЙ` | выдать Pro (например после оплаты через Click/Payme) |
| `/block ID`, `/unblock ID` | заблокировать / разблокировать |
| `/myid` | ваш Telegram ID |

Бесплатный тариф: тесты можно загружать без ограничений, но запускать для группы
можно 1 тест в день и до 30 студентов на запуск (меняется в `.env`:
`FREE_MAX_SESSIONS_PER_DAY`, `FREE_MAX_STUDENTS`; граница «дня» — `TZ_OFFSET_HOURS`, по умолчанию UTC+5).
Pro и админ — без ограничений.

## Сервер для постоянной работы (Linux, Ubuntu)

Подойдёт VPS на 2 ядра и 2 ГБ памяти. Нужен домен (или поддомен), направленный на сервер.

```bash
sudo apt update && sudo apt install -y python3-venv caddy
cd /opt && sudo unzip testbot.zip && cd testbot
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env && nano .env        # BOT_TOKEN, ADMIN_IDS, WEBAPP_URL=https://ваш-домен
echo "WEB_WORKERS=2" >> .env
```

HTTPS-сертификат Caddy получит сам. Файл `/etc/caddy/Caddyfile`:
```
ваш-домен.uz {
    reverse_proxy 127.0.0.1:8080
}
```

Автозапуск — `/etc/systemd/system/testbot.service`:
```
[Unit]
Description=TestRoom bot
After=network.target

[Service]
WorkingDirectory=/opt/testbot
ExecStart=/opt/testbot/.venv/bin/python -m app.main
Restart=always
Environment=HOST=127.0.0.1

[Install]
WantedBy=multi-user.target
```
```bash
sudo systemctl daemon-reload && sudo systemctl enable --now testbot caddy
sudo journalctl -u testbot -f      # логи
```

**Резервная копия:** вся база — один файл `testbot.db`. Копируйте его регулярно
(например, `sqlite3 testbot.db ".backup backup.db"` раз в сутки по cron).

## Проверки

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```
На Windows то же самое делает `test.bat`.

Посмотреть Mini App в обычном браузере без Telegram: в `.env` поставьте `DEV_AUTH=1`,
запустите сервер и откройте `http://localhost:8080/?dev=ВАШ_ID` (ваш ID из ADMIN_IDS — вы
войдёте как учитель; любой другой номер — как студент). Не забудьте вернуть `DEV_AUTH=0`.
39 тестов: разбор всех форматов файлов и ошибок в них, полный сценарий теста, таймер,
лимит сворачиваний, лимиты тарифа, защита чужих данных, подпись Telegram, обработчики бота.

## Нагрузка: сколько выдержит

Замер на сервере с **2 ядрами и 8 ГБ памяти** (генератор нагрузки работал на той же машине
и забирал часть процессора, так что на отдельном сервере результат будет лучше).

| Сценарий | Результат |
|---|---|
| **2000 студентов одновременно**, все входят по коду в одну секунду, на вопрос 5–15 с | 2000 из 2000 закончили, **0 ошибок**; ответ: в среднем **12 мс**, 95% быстрее 67 мс |
| Предельная нагрузка (студенты отвечают без пауз), 1 процесс | ~190 запросов/с |
| Предельная нагрузка, 2 процесса (`WEB_WORKERS=2`) | ~370 запросов/с, 0 ошибок |

Реальный студент отвечает раз в 15–60 секунд, то есть 300+ запросов/с соответствуют примерно
**4000–5000 студентов, пишущих тест в одну и ту же минуту**. Память: ~130 МБ на процесс.

Если одновременно в 2000 человек нажимают «Начать», последний попадает в тест через 5–8 секунд.
В жизни входы распределены по аудиториям, и задержки почти нет.

**Когда расти дальше:** при десятках тысяч одновременных студентов переходите на PostgreSQL
(`DATABASE_URL=postgresql+asyncpg://...`, `pip install asyncpg`) и сервер с 4+ ядрами
(`WEB_WORKERS=4`). Код рассчитан на PostgreSQL, но все замеры выше сделаны на SQLite —
перед переходом прогоните тесты и нагрузочный тест на PostgreSQL.

Свой замер (сервер должен быть запущен):
```bash
python loadtest/load_test.py --url http://127.0.0.1:8080 --students 500 --questions 25 --think 10
```
⚠️ Нагрузочный тест создаёт тестовых пользователей в базе, поэтому запускайте его на копии,
а не на рабочей базе.

## Ограничения, о которых стоит знать
- Без нейросети: формат файла должен соблюдаться. Картинки в вопросах пока не поддерживаются.
- Отслеживание сворачивания срабатывает и на входящий звонок, поэтому по умолчанию тест
  закрывается только после 3 уходов, а не после первого.
- Второй телефон или подсказку соседа никакая программа не отследит.
- `DEV_AUTH=1` позволяет войти в приложение без Telegram. Только для разработки!
